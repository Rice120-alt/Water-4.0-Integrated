# Build and review instructions

These steps are intentionally offline and relative. They do not download
software, modify a game installation, or touch save data.

## Verify the disclosure

From this folder:

```powershell
node build/Verify-Disclosure.js
```

The command checks the required files, privacy scan, and the runtime hash
parity against the sealed candidate when that candidate is present beside this
folder in the working repository. `tools/tests/Test-Water4SourceDisclosure.js`
is the same check from the repository root.

## Lua runtime

The Lua/INI files in `src/runtime` are already source files; no compiler is
required. They are deployed into the corresponding UE4SS `Mods` directory by
the release packaging process. The prebuilt Unreal payload is discussed in the
cooked-asset limitation note and is not regenerated by this command.

## Companion overlays

Install the .NET 8 Windows Desktop SDK, then run the disclosure project files:

```powershell
dotnet publish src/overlay/FWQuestOverlay/FWQuestOverlay.Disclosure.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
dotnet publish src/overlay/WaterDaytimePreparationOverlay/WaterDaytimePreparationOverlay.Disclosure.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

The disclosure projects compile the inspectable logic without redistributing
game artwork. The production candidate embeds local game-derived portraits and
the water icon; a reviewer who wants identical artwork must provide those
inputs locally as described in `assets/README.md`. Missing artwork uses the
source's safe fallback rendering and does not change the Lua integration.

## Packaging boundaries

Do not place MO2, Root Builder, Signature Bypass, RE-UE4SS, .NET installers,
the Steam game, saves, or logs into a source archive. The final game mod ZIP
contains a prebuilt cooked payload because that payload cannot be clean-room
rebuilt from this repository.
